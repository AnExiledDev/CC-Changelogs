Claude Code · Source-level changelog

Version 2.1.252

Several pieces of a reworked prompt system are in this build but switched off. Behind the carved-slate gate (CLAUDE_CODE_CARVED_SLATE, or the remote tengu_carved_slate, default false), Claude Code can send only what changed in your CLAUDE.md instead of the whole block each turn, emit an empty block rather than dropping it when CLAUDE.md has no content so prompt caching holds, and track instruction files as a list separate from memory files. The same gate, plus a tengu_scratch flag, guards a per-session scratchpad directory at <tmpdir>/<session id>/scratchpad that the model is told to use instead of /tmp, skipped entirely for background sessions. Two smaller pieces are also waiting: /context can reuse the tool descriptions actually sent rather than recomputing them, and session configuration now carries a system-prompt append for subagents that nothing yet sets.

The messages Claude Code sends the model when a session's surroundings change now say why they were sent, naming the trigger as session start, compaction, policy refresh, a directory being added, settings sync or an account change, instead of one generic sentence. Task notifications are truncated at 100,000 characters with a warning logged, live for everyone and no flag needed, so one enormous notification cannot bloat the queue. Task output writes got safer and more explainable on macOS: the resolved path is now checked segment by segment against the device and inode of the pinned directory handle, a redirected write is refused and logged, and a directory that resolves to the same underlying location is accepted rather than rejected. When a write is refused, the error now tells you to restart with CLAUDE_CODE_TMPDIR pointing at a fresh directory. Failed session persistence writes in the remote-control bridge are no longer silent, logging [bridge:repl] Internal event write failed and reporting telemetry.

Task output directory errors now tell you how to recover, and macOS aliases are tolerated #

Juicy

Task output errors now tell you to restart with CLAUDE_CODE_TMPDIR set, and macOS aliases no longer break it.

CLAUDE_CODE_TMPDIR
Use it now · Background Tasks
What

When Claude Code refuses to write a task's output because the temporary tasks directory has moved or turned into a symlink, the error now tells you what to do: restart with CLAUDE_CODE_TMPDIR pointing at a fresh directory. On macOS, a directory that resolves to the same underlying location is now accepted instead of refused.

Details
  • Both behaviours are unconditional, no flag.
  • The alias tolerance checks the platform and applies only on macOS, where a path can legitimately resolve to the same device and inode through a different route; other platforms still refuse.
Evidence

restart Claude Code with CLAUDE_CODE_TMPDIR set to a fresh directory

Scratchpad directory for the model's temporary files #

Juicy

Claude can get a private per-session scratch folder instead of writing to /tmp, but it's disabled here.

CLAUDE_CODE_CARVED_SLATECLAUDE_CODE_SESSION_KIND
Not switched on · Session Environment
What

Claude Code can hand the model a private per-session directory for scratch files, at <tmpdir>/<session id>/scratchpad, with a system prompt line telling it to use that instead of /tmp. It is off in this build: it requires both the tengu_scratch flag (or an artifact-tool eligibility check) and the carved-slate flag, which reads CLAUDE_CODE_CARVED_SLATE or the remote tengu_carved_slate and defaults to false. It is also skipped entirely when CLAUDE_CODE_SESSION_KIND is bg.

Details
  • Both flags default to false, so nothing is created or announced unless they are turned on.
  • A matching withdrawal path tells the model the directory is no longer available.

Task notifications capped at 100,000 characters #

Huge task notifications get trimmed at 100,000 characters so they don't clog the queue.

You'll notice · Elsewhere
What

Notifications produced by tasks are now truncated to 100,000 characters before being queued, with a warning logged when that happens. This is live for everyone with no flag, and stops a single huge task notification from bloating the queue.

Details
  • Applies only to queued notifications of the task-notification kind.
  • The log line reports the original and truncated lengths.

Stricter check that task output is written to the intended directory on macOS #

On macOS, task output is refused if a symlink or swapped directory would redirect where it lands.

You'll notice · Task Output
What

On macOS, before writing task output Claude Code now verifies that the resolved path really is the directory it pinned earlier, walking each path segment and comparing the device and inode against the pinned handle rather than trusting the path string. If a symlink or replaced directory redirects the write, it is refused and logged as a warning. On other platforms the check returns false immediately and nothing changes.

Details
  • Refusals log the resolved path and the reason: not reachable by a link-free route.
  • Failures swapping task output into place now include text telling you how to recover.
  • No feature flag; active on macOS in this build.
Evidence

pinWriteTarget: ${w} resolves to ${O}: not the same directory by a link-free route; refused
