Version 2.1.221

This release upgrades the bundled MCP SDK to support the new 2026-07-28 protocol revision, including subscription streams, multi-round-trip input_required requests, and envelope-based protocol negotiation. It also brings AWS SigV4 re-signing to the sandbox TLS proxy, enhanced credential masking with regex extraction, a new --autocompact CLI flag, revised background session shipping guidance, and an updated persistent memory instruction prompt.

--autocompact CLI Flag #

New
What

Configure the auto-compact token window at session launch from the command line, without needing to use the /autocompact slash command inside a session.

Usage
claude --autocompact auto
claude --autocompact 500k
claude --autocompact 200000
Details
  • Accepts auto or a token count between 100k and 1M (e.g. 500k, 200000, or shorthand 200 for 200k)
  • Equivalent to running /autocompact once the session starts, but applied before the first turn
  • Error message if the value is invalid: "It must be 'auto', or between 100k and 1M (e.g. 500k, 200000, or 200 as shorthand)"
  • Previously the window was only configurable inside a running session via the slash command
Evidence

New CLI option declaration (search for "--autocompact <auto|tokens>")

MCP Protocol 2026-07-28 Support #

New
What

The bundled MCP SDK now implements the 2026-07-28 protocol revision, enabling a set of new server capabilities and stricter protocol negotiation.

Details
  • subscriptions/listen streaming: Servers can push tool, prompt, and resource change notifications over a persistent SSE stream instead of requiring the client to poll. The client now opens a subscriptions/listen connection on connect and automatically re-opens it if it drops.
  • input_required round-trips: Servers can return an input_required result from tools/call, prompts/get, or resources/read, embedding sub-requests (elicitations, sampling, roots/list) that the client fulfils before the original request retries. Controlled by inputRequired.autoFulfill and inputRequired.maxRounds.
  • Envelope-based negotiation: Requests in the modern era carry a _meta envelope with io.modelcontextprotocol/protocolVersion and io.modelcontextprotocol/clientCapabilities headers. Mismatches are rejected with -32020 HeaderMismatch.
  • server/discover: Used to probe and negotiate the protocol version before the full initialize handshake. Version-pinning is available via versionNegotiation: { pin: '2026-07-28' }.
  • Task management: New tasks/create, tasks/get, tasks/update, tasks/delete, tasks/list methods for servers that support task tracking.
  • x-mcp-header tool extension: Tool input schema properties may declare x-mcp-header to have their value passed as an HTTP header rather than in the JSON body. Only supported on flat primitive properties.
Evidence

Protocol version constant (search for "2026-07-28"), subscription stream (search for "subscriptions/listen"), input_required (search for "input_required")

AWS SigV4 Re-signing in the Sandbox TLS Proxy #

New
What

The sandbox's TLS termination proxy can now re-sign AWS SigV4 requests on behalf of tools, so that masked AWS credentials (whose placeholder values would otherwise cause signature failures) are transparently re-signed with the real credentials before the request reaches AWS.

Details
  • Enabled when credential masking is configured for both accessKeyIdVar and secretAccessKeyVar (e.g. AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY)
  • Supports standard AWS4-HMAC-SHA256 header signatures and presigned URL signatures
  • Body hashing is handled automatically; requests with a literal body hash are buffered and re-hashed (with a configurable byte limit — default 5 MB; requests that exceed the limit are denied)
  • AWS4-ECDSA-P256-SHA256 (SigV4A) requests are detected but denied by default; configure credentials.sigv4.sigv4a to passthrough if needed
  • Session token (AWS_SESSION_TOKEN) is forwarded automatically when present
  • Warning is emitted if the secret key is masked but the access key ID is not — both must be masked for re-signing to work
  • Set credentials.sigv4.streaming and credentials.sigv4.presigned policies to control what happens with streaming-signed and presigned requests
Evidence

Re-signing infrastructure (search for "AWS4-HMAC-SHA256"), credential registry (search for "[credential-aws] registered SigV4 pair for")

Artifact Comment Thread Replies and Auto-Edit #

New
What

Claude can now participate in comment threads on published claude.ai artifacts — reading threads, posting replies, and (when granted edit permission by a thread writer) automatically editing the artifact in response to feedback.

Details
  • Automatic activation: When a human activates Claude on an artifact's comment thread, Claude receives a notification and can read and reply to the thread using the Artifact tool with action: "comments" or action: "reply".
  • action: "comments": Reads all comment threads on an artifact URL, returning thread IDs, comment text, and resolution state.
  • action: "reply": Posts a reply to a specific thread (identified by thread_id from a prior comments call). Reply text is plain text, at most 4096 UTF-8 bytes.
  • Auto-edit: If a thread writer activates Claude with edit capability, Claude may update the published artifact directly in response to the thread discussion.
  • Auto-reply rate limiting: Auto-replies are paused when an hourly cap is reached, or when the session is in plan mode.
  • Replies appear to artifact viewers as "Claude · via the user" or "Claude (via viewer ...)".
Evidence

Reply action (search for "post a reply comment on an artifact thread"), auto-reply disclosure (search for "artifact auto-reply")

Enhanced Sandbox Credential File Masking #

New

The mask mode for sandbox.credentials.files entries now supports structured extraction, so only specific fields of a credential file are replaced rather than the entire file content.

New fields on file mask entries:

  • extract — a regular expression applied globally to the file; capture group 1 of each match is the credential value to mask. Without extract, the whole file is replaced with a sentinel (previous behavior, still the default).
  • maskDuplicates — if true, verbatim occurrences of the captured credential value outside the regex-matched spans are also replaced. Intended for long, high-entropy secrets only.
  • injectHosts — array of hostnames for which the real credential value is injected by the proxy. When injectHosts is empty, sandboxed commands see only the sentinel and the proxy does not inject.
  • onExtractNoMatch — behavior when extract matches nothing: "warn" (default, fail-open), "deny" (block reads of the file), or "error" (abort sandbox setup).
Evidence

New Zoc() validation function (search for "extract must contain at least one capturing group"), new onExtractNoMatch setting (search for "onExtractNoMatch")

Background Session Shipping Guidance Revised #

New

The instructions given to Claude in background (headless) sessions about when and how to commit and push have been updated to be more nuanced:

Old behavior: Claude was instructed to "open a draft PR via gh pr create --draft without asking — never end the job with uncommitted work" once isolated in a worktree.

New behavior:

  • "If you made code changes in a worktree you entered, commit before finishing — you don't need to ask — and push if the repository has a remote."
  • "Open a draft PR when the task calls for one" (previously unconditional).
  • Subagents are now explicitly exempt: "If you're running as a subagent, the git guidance above and this report don't apply: return your work to your caller."
  • Sessions now end with a structured report: what was done, where it lives (path, branch, PR, or the answer), and the next command if one is needed.
Evidence

Updated background session prompt (search for "If you made code changes in a worktree you entered, commit before finishing")

Memory Instruction Prompt Rewritten #

New

The system prompt that governs Claude's persistent file-based memory has been substantially rewritten with clearer, more precise criteria.

Key changes:

  • Three explicit requirements for a memory to be saved: it must be applicable (changes future behavior), durable (applies across multiple sessions), and legible (readable without the original context). All three must hold.
  • Added a scope-words test: words like "never…" / "always…" / "whenever you…" signal durability; "this time…" / "for now…" signal a one-off that should not be saved.
  • Clarified that only lessons the user taught are saveable — not things Claude worked out on its own about code, tools, or its own mistakes.
  • Removed the previous instruction to save "every correction" and replaced it with a more conservative rule: save only if the lesson is both durable and applicable.
  • Up to 4 memories can be pinned (apply to every future session).
Evidence

New memory prompt (search for "You must NOT save a memory unless you have validated that it is applicable, durable, AND legible")

Windows Sandbox Persistent CA Validation #

New

The Windows sandbox now validates that user-supplied TLS inspection CA certificate files are well-formed before trusting them:

  • The certificate and private key must parse successfully
  • The key must be RSA
  • The notBefore validity date must be in the past
  • The key must match the certificate's public key
  • The certificate thumbprint must be extractable

Informative error messages are emitted for each failure mode, making it easier to diagnose misconfigured CA setups.

Evidence

New jbo() CA validation function (search for "key does not match certificate public key")

Session Transcript Logging [In Development] #

Dev
What

A dated, file-based transcript log for sessions — each session's transcript would be written to a path like ~/.claude/logs/YYYY/MM/DD/<session-id>-<title>.md.

Status

Feature-flagged (tengu_hazel_quire). Also requires the session to not be in a daemon context (vu() !== null check).

Details
  • Activation requires three conditions simultaneously: (1) the session is not running in a daemon/subprocess context (vu() !== null returns false), (2) the auto-memory feature is enabled (isAutoMemoryEnabled / Hm()), and (3) the tengu_hazel_quire GrowthBook flag is on. If auto-memory is disabled, session logging is also disabled regardless of the flag.
  • Log directory is $CLAUDE_CONFIG_DIR/logs/YYYY/MM/DD/ — a date-stamped tree built by luy() using the wall clock at session open time.
  • Log filename is <sessionId8chars>-<slug>.md, where the session ID is truncated to the first 8 characters (_Tu = 8) and the slug is derived from up to 5 words of the session title (max 40 chars via Jir()). If the title is empty or unavailable, the filename is simply <sessionId8chars>.md.
  • The activeSessionLogExcluder (nfs()) function returns a path-test closure used to prevent the session's own transcript log from being loaded back into auto-memory recall: it matches any relative path that starts with logs/ and whose basename equals <sessionId8chars>.md or starts with <sessionId8chars>-.
  • Infrastructure is complete; the feature activates when the tengu_hazel_quire flag is enabled server-side.
Evidence

isSessionLogEnabled gate (cuy()) (search for "tengu_hazel_quire"), path builder (auy() / getAutoMemSessionLogPath), date-directory builder (luy()), log-file excluder (nfs() / activeSessionLogExcluder)

Thrifty Sonic Mode [In Development] #

Dev
What

A new efficiency/cost-saving mode for Claude Code, controlled by a feature flag.

Status

Feature-flagged (tengu_thrifty_sonic). Can also be enabled via the environment variable CLAUDE_CODE_THRIFTY_SONIC.

Details
  • Blo() returns process.env.CLAUDE_CODE_THRIFTY_SONIC ?? Je("tengu_thrifty_sonic", false) — environment variable takes precedence over the GrowthBook flag.
  • The computed value is cached as Wfp = Yr(() => OU() && Blo()): Thrifty Sonic is only active when both operator/headless mode (OU()) is on and the flag or env-var is truthy. It has no effect in normal interactive sessions.
  • Bash tool system-prompt simplification: When Wfp() is true, the Bash tool's description discards the standard "IMPORTANT: Avoid using this tool to run find, grep, cat, head, tail, sed, awk, or echo…" block and the "use the appropriate dedicated tool" guidance entirely, and substitutes a single line: "Communication: Output text directly (NOT echo/printf)". The model is no longer steered away from running shell utilities for file operations.
  • bashFirst auto-mode injection: When the session is in auto mode and Blo() is true and the tool set includes the Bash tool alongside at least one dedicated file tool (Read/Glob/Edit), the auto_mode context attachment is emitted with bashFirst: true. This injects an additional system-level instruction: "Do your work through the [Bash] tool wherever it can accomplish the job: read files with cat, head, or sed -n, search with grep and find, and make file changes with sed, heredocs, or short scripts, rather than using the dedicated Read/Edit tools. Fall back to a dedicated tool only when [Bash] genuinely cannot do the job."
  • When auto mode exits with bashFirst: true active, a follow-up message is injected: "Resume using the dedicated tools for file reads, searches, and edits."
  • The net effect is a cost-reduction strategy: the model is directed to perform file reads, searches, and edits through shell commands (fewer API round-trips to dedicated tools) rather than the structured tool calls that require more tokens.
Evidence

Flag resolver Blo() and cached gate Wfp (search for "tengu_thrifty_sonic"); Bash description branch (search for "Wfp()"); bashFirst injection in pDb() and auto-mode attachment rendering

GrowthBook Refresh Interval Control [In Development] #

Dev
What

The interval at which Claude Code refreshes its GrowthBook feature flags can now be tuned via a server-side flag, enabling Anthropic to speed up or slow down flag refresh rates across the fleet.

Status

Feature-flagged (tengu_gb_refresh_interval_minutes). Default remains 360 minutes (6 hours).

Details
  • The dTu() builder reads Je("tengu_gb_refresh_interval_minutes", null). If the flag is absent, it returns the unchanged default of 360 minutes and flagged: false. If the flag is present, the value is coerced to a number (accepts numeric strings), clamped to [5, 360] minutes, and jittered ±10%: Math.round(Math.min(o (0.9 + Math.random() 0.2), 360) 60 1000). The Math.min(..., 360) hard-cap inside the jitter expression ensures that even a 10% upward jitter on a 360-minute value cannot exceed 360 minutes.
  • Invalid flag values (non-finite, zero, negative) silently fall back to the default 360-minute interval; flagged is still returned as true in that case, so the double-refresh logic activates regardless.
  • The refresh loop (tuy()) uses flagged to decide whether to make a second refresh pass: if the first UZr() call did not change the cached flag state (zps === n), the loop waits an additional random delay of 0–5000 ms (Math.round(Math.random() * euy), where euy = 5000) then calls UZr() a second time. This "catch-up" pass is intended to detect new flag values that propagate to the GrowthBook backend shortly after the first poll.
  • On any refresh error, the loop falls back to a fixed 60-second wait (Zcy = 60000 ms) before the next attempt.
  • The flag controls only the inter-refresh interval; the actual flag-fetch logic in UZr() is unchanged.
Evidence

Interval builder dTu() (search for "tengu_gb_refresh_interval_minutes"); refresh loop tuy() showing flagged branch and euy = 5000 / Zcy = 60000 constants
