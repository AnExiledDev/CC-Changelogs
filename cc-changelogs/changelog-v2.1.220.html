Clearer beta-header retry log message #

New

When Claude Code sends a beta API header and the server rejects it with HTTP 400, it retries without that header and logs a debug message. The wording of that message was tightened for clarity.

Before: "beta rejected (HTTP 400) and the bare retry succeeded — dropping the beta for the rest of the session" After: "beta rejected (HTTP 400) and the retry without it succeeded — dropping the beta for the rest of the session"

This only appears in debug output and has no effect on behaviour.

Evidence

Auto-mode classifier API header [In Development] #

Dev
What

A new API beta header auto-mode-classifier-2026-07-16 is now conditionally sent with requests. This header likely enables a server-side routing or response-mode classification feature.

Status

Feature-flagged — only sent for first-party Anthropic users who pass two additional internal checks (HP() and Yd()). Not active for standard users.

Details
  • Previously, the function responsible for supplying extra beta headers (COd) unconditionally returned an empty array — no extra headers were ever added via this path
  • The replacement function (ROd) now checks: is this a first-party session? Are both internal gates passing? If yes, it appends the auto_mode_classifier header with value auto-mode-classifier-2026-07-16
  • The header value follows the same dated-slug pattern used by other Anthropic beta headers
Evidence

new header constant Sji = WA("auto_mode_classifier", "auto-mode-classifier-2026-07-16") added to the request-header registry (search for "auto-mode-classifier-2026-07-16"); ROd replaces the old always-empty COd stub

Claude Opus 5 model constant [In Development] #

Dev
What

A new model identifier claude-opus-5 has been registered internally, along with gating logic that deliberately excludes it from normal model resolution and fallback paths.

Status

Stubbed — the constant exists and detection functions are wired up, but the model is explicitly filtered out of all fallback resolution so users cannot reach it through any current code path.

Details
  • New constant: rdg = "claude-opus-5"
  • New predicate Xkt() returns true only when: auth type is firstParty, a subscription check passes, a specific exclusion flag is absent, no custom model is set, and no other models are in the tried-models list — a very narrow set of conditions
  • New predicate u2c(e) returns Xkt() && model === "claude-opus-5" — identifies the new model under those narrow conditions
  • The model-resolution fallback function (f2c) now explicitly skips any candidate where u2c(n) is true, meaning claude-opus-5 is actively excluded from fallback selection
  • A separate constant XMu = "claude-opus-4-8" was also added as a named reference to the existing claude-opus-4-8 model (refactoring, no behaviour change)
Evidence

rdg = "claude-opus-5" constant (search for "claude-opus-5"); fallback exclusion via !u2c(n) filter in model resolution (search for "claude-opus-4-8" for the companion constant)
