Version 2.1.232

This build carries 61 features that are compiled in but not reachable, and 12 of them are worth naming. A built-in web-fetch subagent would take page fetching away from the main conversation entirely, returning a summary instead of raw text and optionally saving binary downloads like PDFs to disk, but it needs CLAUDE_CODE_WEB_FETCH_AGENT or the server flag tengu_clever_orbit, both off. Cross-session messaging work is similarly dark: a /config row for "Messages from your other sessions" with default, accept, hold and refuse, @-mentioning other running sessions, and cloud sessions as message targets all wait on CLAUDE_CODE_HARBOR_KITE or flags that fall back to false. Two separate artifact "live doc" collaborative paths are complete down to refusal messages and consent text, but hang off an internal module reference that is set to null and never assigned. Also present and unreachable: a per-session proactivity level whose picker sits behind a gate nothing sets, and checkpointing your working tree to a hidden git ref before a rate limit ends the session.

Forked subagents are now on by default for interactive sessions, with the remote rollout flag gone and only CLAUDE_CODE_FORK_SUBAGENT=false left to turn them off. You can address another session by writing @name or @"name" in a prompt, with an optional [ref] when the name is ambiguous. permissions.disableAutoMode set to "disable" stops Claude Code from ever falling back into auto mode, /context now returns machine-readable usage figures including total_tokens, percentage and an over_limit block to SDK consumers, and settings.json can set OTEL_SERVICE_NAME, OTEL_TRACES_EXPORT_INTERVAL and CLAUDE_CODE_FORK_SUBAGENT in its env block. Rotated client certificates are re-read on TLS errors without a restart when CLAUDE_CODE_CLIENT_CERT is configured, and subagents can now be primed with your saved memory unless CLAUDE_CODE_DISABLE_AUTO_MEMORY is set. That is 12 of 192 shipped entries.

Deep review no longer ends by publishing its findings as an HTML artifact with a paste-this-URL-back message; findings come back as JSON. /code-review always runs inline now, with the scripted background workflow branch deleted. Spawning a worker blanks inherited resume variables including CLAUDE_CODE_RESUME_PROMPT and CLAUDE_CODE_REMOTE_SESSION_ID, so a child no longer picks up the parent's resume target. Remote Control drops a late or duplicate answer quietly instead of raising an unsigned-activity notice, proxy redirect destinations are parsed as URLs before being followed, and the auto-mode setup scan aborts with no_model rather than starting a scan that cannot work.

Claude Desktop's full managed-configuration schema is now inlined into the CLI, covering inference providers, MCP server policy, egress restrictions and OTLP settings, along with a Zod validation runtime. The managed-settings policy helper takes one entry per platform plus an optional default entry that is a static settings payload, so a helper that fails at startup falls back without spawning a process. Fork-subagent enablement now checks the environment variable first and caches its answer on the session config instead of a module-level variable.

You'll notice · MCP
What

When an HTTP-based MCP server answers the capability probe with a response that does not match the request or that cannot be decoded, Claude Code now treats the server as an older one that predates the discovery protocol and moves on, instead of hanging or surfacing a raw error.

Details
  • Two outcomes are distinguished: a reply whose id does not echo the request, and a reply that fails JSON or schema decoding.

  • A stream ending early is now reported separately from a send failure, via a dedicated end-of-stream callback.

Cross-session messaging refuses to bind on an unsafe sockets directory #

Juicy

Unsafe socket directories turn cross-session messaging off, with a hint about XDG_RUNTIME_DIR and CLAUDE_CODE_TMPDIR.

XDG_RUNTIME_DIRCLAUDE_CODE_TMPDIR
Use it now · Session Messaging
What

Before opening its local messaging sockets, Claude Code now walks every component of the socket directory path and refuses unsafe ones: symlinks owned by another user, non-directories, world- or group-writable directories without the sticky bit, symlink loops past 16 levels, and dangling links. On refusal, cross-session messaging is simply off for that session rather than binding anyway, and you get a remediation hint naming XDG_RUNTIME_DIR and CLAUDE_CODE_TMPDIR.

Details
  • The refusal is recorded as socket_dir_refused and logged at error level, with a classified cause such as directory_rule, foreign_owner, leaf_shape, raced or symlink_loop, each mapped to its own hint.
  • The directory is created with mode 0700, and chmod'ed back to 0700 if it is found looser.
Evidence
