Claude Code · Source-level changelog

Version 2.1.222

This release delivers a comprehensive rewrite of worktree isolation verification with much more precise git identity checks, a new "local" vs "session" scope for model fallback events (so subagent refusals no longer appear to affect your whole session), and remote bridge self-healing on heartbeat loss. Remote Control can no longer be enabled from repo-scoped settings, closing a security gap. Skill and plugin manifests gain a new open metadata field for authors.

Fallback Model Scope: Local vs Session #

New

When a refusal triggers a fallback to a different model, Claude Code now distinguishes two scopes:

  • session — the main thread was flagged; the session model is swapped for the rest of the conversation. The /model display now reads "(automatically switched from X after a message was flagged — run /model to switch back)" to make this visible.
  • local — a subagent, /btw side-question, or background fork was flagged; only that single response came from the fallback model and the session model is unchanged. A footnote "Your session model is unchanged." appears with the fallback notice.

This distinction is also surfaced in the SDK event stream via the new scope field on model_refusal_fallback events ("session" | "local"). Older CLIs that do not emit this field should be treated as "session".

Evidence

new scope field in model_refusal_fallback events (search for "Your session model is unchanged.") — zPo / dkd at line ~653125

Worktree Isolation: Full Git Identity Verification #

New

Agent and session worktree resume now performs a thorough multi-step git identity check before entering or resuming a worktree. The previous approach only resolved paths; the new approach runs git rev-parse --absolute-git-dir --show-toplevel --git-common-dir, then cross-checks:

  • Whether the .git entry is a symlink (disqualifies the tree)
  • Whether the common dir is the same as the git dir (linked worktree vs main checkout)
  • Whether the gitdir back-pointer matches the expected location
  • Whether any symbolic links exist in the ref storage directories
  • Whether the working tree top-level resolves to the expected path (detects core.worktree redirects)
  • Whether the tree is or contains the session's own launch directory (prevents forged resumes)

New error classes AgentResumePermanentlyRefusedError and AgentResumeTransientError let callers distinguish recoverable failures (retry; binding kept) from permanent ones (rebind required). Worktree-related rejection reasons are now reported as tengu_worktree_resume_root_rejected analytics events.

Details
  • GIT environment variables (GIT_DIR, GIT_COMMON_DIR, GIT_WORK_TREE, GIT_CONFIG_KEY_*, etc.) are now scrubbed from the environment before verification runs, so ambient git state cannot pollute the identity check.
  • If a worktree cannot be verified this attempt, the binding is kept and the next --resume will retry automatically.
  • If a worktree is confirmed invalid (poisoned record, wrong repository, own launch tree), the binding is cleared and the session falls back to the current directory.
Evidence

git verification infrastructure (search for "Refusing to use" + "as an isolation worktree") — ebo() at line ~216466

Skill and Plugin metadata Frontmatter Field #

New

Both skill SKILL.md frontmatter and plugin manifests now accept a metadata field — a free-form map for the skill or plugin author's own use (for example, entitlement flags or catalog fields).

  • For skills: the value is preserved on the loaded skill object. Claude Code does not read or act on it.
  • For plugins: the value is preserved on the parsed manifest but not read by Claude Code.

This allows skill/plugin authors to attach arbitrary structured data that survives load without Claude Code imposing any schema on it.

Evidence

Remote Control Cannot Be Enabled from Repo-Scoped Settings #

New

Setting remoteControlAtStartup: true in project or local settings (settings.json, .claude/settings.json) is now ignored with a logged warning. Remote Control is a security-sensitive capability that can only be enabled at user scope (via /config or user settings.json).

A value of false in repo-scoped settings is still honoured and acts as a hard off-switch. Only the true direction requires user scope.

The warning reads: "remoteControlAtStartup: true in project and local settings ignored — repo-scoped settings cannot enable Remote Control; set it at user scope (/config)"

Evidence

security gate (search for "repo-scoped settings cannot enable Remote Control") — Y_t() at line ~681628

Remote Bridge Heartbeat Self-Healing [Gradual Rollout] #

New

Controlled by tengu_bridge_selfheal_heartbeats, which defaults to true (on for everyone unless Anthropic rolls it back server-side).

When CCR v2 detects that presence heartbeats are failing while the SSE channel is still healthy, the bridge now proactively closes the transport (with code 4093) and rebuilds it rather than leaving the connection in a degraded state. This is visible in logs as "[bridge:repl] CCR v2: heartbeats failing while SSE healthy — closing for transport rebuild".

Recovery attempts are budget-limited: if the bridge rebuilds too many times within one hour, it gives up and shows "presence heartbeats to the server kept failing after repeated reconnects" as a terminal error.

Evidence

Subagent Model Allowlist: Family-Based Fallback #

New

When a subagent requests a model not in the availableModels allowlist, Claude Code now tries to find the newest allowed model in the same model family before falling back to the parent model. The log warning distinguishes the two outcomes:

  • "using the newest allowed model in its family" — a same-family substitute was found
  • "inheriting the parent model" — no same-family substitute; parent model is used

AUQ Park Preservation Across Shutdown [In Development] #

Feature-flagged — tengu_cinder_heron controls whether "park" (AskUserQuestion requests that paused for user input) are preserved when the session shuts down. The flag reads Qe("tengu_cinder_heron", "off") === "preserve" — it is "off" unless Anthropic sets it to "preserve" server-side.

Remote Control Setting Migration #

New

If your settings.json (project or local scope) has "remoteControlAtStartup": true, it will now be silently ignored with a log warning. Move the setting to your user-level settings.json or toggle it via /config to preserve the behaviour.

Worktree Resume: Transient vs Permanent Failures #

New

The new error taxonomy (AgentResumeTransientError vs AgentResumePermanentlyRefusedError) changes how failed resumes are retried by callers. Transient failures keep the binding and retry on the next --resume. Permanent refusals clear the binding. If you see "Cannot resume this agent: its worktree…" errors, check whether they are transient (network/git unavailable) or permanent (the worktree path is invalid or poisoned) before deciding whether to recreate the worktree.
