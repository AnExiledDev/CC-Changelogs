Version 2.1.219

Version 2.1.219 introduces Claude Opus 5 as the new primary model, adds a pinned memory system that automatically injects selected memories into every conversation, and introduces a new DirectoryAdded hook type. The release also includes significant improvements to workshop live-edit safety, MCP server validation, and model fallback behavior.

Claude Opus 5 Support #

New

Claude Opus 5 is now the default and recommended model in Claude Code. The model picker has been updated to reflect this, with Opus 5 labeled "best for everyday, complex tasks" and Opus 4.8 demoted to "Previous Opus version."

Details
  • New model IDs recognized: claude-opus-5, anthropic.claude-opus-5, us.anthropic.claude-opus-5
  • An Opus 5 with 1M context variant (claude-opus-5[1m]) is also available for long sessions with large codebases
  • Fast mode (/fast) now supports Opus 5 in addition to Opus 4.8 and 4.7
  • The model picker description for Opus 4.8 now reads "Opus 4.8 · Previous Opus version" (search for "Opus 4.8 - previous Opus version")
  • Model description line updated: "The most recent Claude models are the Claude 5 family and Haiku 4.5" (Opus 4.8 removed from the headline list)

Pinned Memories #

New

Memory files can now be marked as "pinned" using a metadata frontmatter field. Pinned memories are automatically injected at the start of every conversation under the heading # Pinned memories (apply to every conversation), making them available without the model needing to look them up.

Usage

Add the following frontmatter to any memory file to pin it:

---
name: my-preference
description: My team's coding conventions
metadata:
  pinned: true
---

Your memory content here.
Details
  • Pinned memories are scanned each session and injected into the system prompt automatically
  • The feature is gated behind tengu_gable_onyx_sluice and tengu_larch_pavise flags (gradual rollout)
  • Pinned memories appear in context under the XML-like tag <pinned-memory path="...">...</pinned-memory>
  • Up to a configurable cap of pinned files are injected; files exceeding the limit are dropped with telemetry logged
  • The AutoMemPinned type is used internally to track these injected memories (search for "AutoMemPinned")
Evidence

New memory scan infrastructure (search for "# Pinned memories (apply to every conversation)")

DirectoryAdded Hook #

New

A new DirectoryAdded hook event type fires whenever a working directory is added to the session mid-run, either via the /add-dir slash command or via an SDK register_repo_root control request.

Usage

Configure the hook in your settings.json or settings.local.json:

{
  "hooks": {
    "DirectoryAdded": [
      {
        "matcher": "",
        "hooks": [{ "type": "command", "command": "echo 'Directory added'" }]
      }
    ]
  }
}
Details
  • The hook payload includes Absolute path of the directory that was added and How the directory was added: "slash_command" for /add-dir, "register_repo_root" for the SDK control_request
  • Hook execution failures are logged with the messages "DirectoryAdded hook exec failed:", "DirectoryAdded hook execution failed:", and "DirectoryAdded hook failed:"
Evidence

New hook event type (search for "DirectoryAdded")

/add-dir Scope Expanded #

New

The /add-dir command now accepts directories that are subdirectories of directories passed at launch via --add-dir, in addition to subdirectories of cwd.

Before: Directories added mid-session had to be strict subdirectories of the current working directory.

After: Directories added mid-session can be subdirectories of cwd or of any directory passed at launch via --add-dir.

Evidence

Updated /add-dir description (search for "is not a subdirectory of cwd or of a launch-time --add-dir root")

Workshop Live-Edit Now Blocked for Workshop Pages #

New

Live-edit (direct in-place editing of a published artifact) is now blocked when the target artifact is a workshop page. This prevents bypassing the publish-time validation that ensures workshop HTML integrity.

When attempting to live-edit a workshop page, you will now see:

live-edit is not available on workshop pages — edit the local workshop file and republish; the publish path is the validation chokepoint live-edit would bypass

If the page's workshop nature cannot be verified due to a transient network failure, you'll see a more specific message with a retry suggestion.

Evidence

New workshop live-edit guard (search for "live-edit is not available on workshop pages")

Memory Sync Error Messages Now Include Resolution Steps #

New

When memory sync is disabled due to a directory conflict, the error messages now include specific resolution steps with timing information.

Before (mount_dir_foreign_partition): > Memory sync is disabled for this file's directory: it contains sync state from a different memory store (mount_dir_foreign_partition). This write was saved locally but is NOT being synced…

After: > Memory sync is disabled for this file's directory: it already holds the synced memory of a different memory store (mount_dir_foreign_partition), so writes here are saved locally but are NOT synced to shared/server memory. To resolve it, rename or relocate the conflicting directory team/[name]/ — sync re-enables automatically on the next sync cycle once it is out of the way (within the hour at most, sooner on the next write or restart); deleting it instead discards any unsynced files inside it…

Similar improvements apply to mount_dir_unmanifested_nonempty. Both messages now instruct the model to tell the user about the conflict.

Evidence

Improved sync error messages (search for "condition cleared — re-adopting the mount dir")

CLAUDE_CODE_GIT_BASH_PATH No Longer Crashes on Bad Path #

New

Previously, setting CLAUDE_CODE_GIT_BASH_PATH to a path that didn't exist would cause Claude Code to exit with process.exit(1). Now it validates both that the path exists and that the file is actually a bash/sh binary (bash.exe, sh.exe, bash, sh), logs a warning with details, and falls back to auto-detection.

New warning messages:

  • If the file doesn't exist: CLAUDE_CODE_GIT_BASH_PATH "[path]" not found; falling back to auto-detection
  • If it exists but isn't a bash/sh binary: CLAUDE_CODE_GIT_BASH_PATH "[path]" is not a bash/sh binary; falling back to auto-detection
Evidence

Improved path validation (search for "is not a bash/sh binary")

MCP Policy URL Variable Expansion Safety #

New

When MCP policy URL predicates use ${VAR} variable substitution, the expansion is now checked for unsafe patterns:

  • Variables that inject wildcard semantics (*)
  • Variables that restructure the URL (inject /, ?, #, etc.)
  • Variables whose values span authority or scheme positions when they shouldn't

A warning is logged for unsafe expansions, and allowlist URL entries using such variables fail closed (deny by default). Denylist entries are not affected.

Evidence

New URL expansion safety check (search for "MCP policy URL predicate expansion was unsafe")

Artifact PR Review Skill Rebuilt as Template-Filling Flow #

New

The artifact-pr-review skill has been substantially updated. It now uses a four-step template-filling flow where the model authors a JSON object and fills a bundled HTML template directly, rather than passing a payload to the Artifact tool's pr_review input. This gives the model full control over the page HTML while maintaining strict validation at publish time.

Key changes:

  • Step 1: Gather the PR (unchanged)
  • Step 2: Author a JSON "generated" object (new schema, with explainer blocks, synthesis, concerns)
  • Step 3: Fill the bundled template from the JSON, wire the staleness signal and decision pills manually
  • Step 4: Publish the filled HTML with the Artifact tool

The validation contract is more explicit: the model must HTML-escape all PR-derived strings, validate JSON fields against length limits, and ensure no external resources are referenced.

Evidence

Skill rewrite (search for "fill the bundled template" and "SLOT:")

Bug Fixes

7 items
  • Shell command detection for memory deletion now uses a compiled regex (rm|remove-item|ri|del|erase) rather than an inline pattern, improving consistency and adding Windows PowerShell removal commands (remove-item, ri, del, erase) (search for "rm|remove-item|ri|del|erase")
  • The --teleport repo mismatch error now correctly handles hostname differences by stripping port numbers before comparison and using a helper function to format the session/current repo display (search for "Vvo" function with sessionDisplay/currentDisplay)
  • Conversation cleanup on shutdown (findUnresolvedToolUse) now correctly handles the case where tool results were interrupted by shutdown, preventing false "unresolved tool use" reports in sessions that ended abruptly (search for "interruptedByShutdown")
  • MCP OAuth flow attempt IDs are now hashed before being sent to telemetry, preventing raw UUIDs from appearing in analytics data (search for "tengu_mcp_oauth_flow_start")
  • The org memory discovery conflict-resolution logic now correctly delegates to the shared fnu() helper rather than duplicating the logic inline (internal refactor, no user-facing change)
  • Plan slug collision detection now checks for sidecar file paths in addition to .md paths, preventing overwrite issues when plan files have associated sidecar content
  • The daemon upgrade check now requires that both versions parse as semver and belong to the same semver "engine" before comparing version numbers, preventing cross-build-channel upgrade attempts (search for "phn" function checking pre-release tags)

Notes

The artifact-pr-review skill has changed its publish mechanism from the Artifact tool's structured pr_review input to direct HTML template filling. Sessions that have the old skill cached may need to be refreshed. If you see "composed review publishing is not enabled in this session", start a new session to pick up the updated skill.

The __proto__ MCP server name restriction is a breaking change for any configuration using that exact name. Rename the server in your MCP config.
